## Build fix 1 — Wrangler generated types

`worker-configuration.d.ts` is generated by `wrangler types` and must not be shipped as a hand-written source file.
The repository ignores this file and every `typecheck`/`test` run generates it from `wrangler.toml` first.
This avoids Wrangler 4.x aborting with `A non-Wrangler worker-configuration.d.ts already exists`.

## Build Fix 1

Cloudflare deployment exposed a bootstrap conflict: the first snapshot contained a manually-authored `worker-configuration.d.ts`, but the build runs `wrangler types`, which owns that output path.

The fix removes the manual file and ignores the generated file. `wrangler types` remains the source of truth for runtime and `Env` bindings.
